# Story 1.16: MarkdownV2 Support

## Status
- Ready for Review

## Story
**As a** user,
**I want** all bot messages to be formatted using MarkdownV2,
**so that** I can receive visually consistent and richly formatted communications.

## Acceptance Criteria
- **AC1 (markdown-v2 mode enforced)**: All messages sent by the bot must use `parse_mode='MarkdownV2'`.
- **AC2 (escape utility added)**: A new utility function `escape_markdown_v2` must be created in `src/utils/formatters.py` to handle escaping of special characters.
- **AC3 (dynamic data escaped)**: All dynamic data (e.g., channel names, video titles, user input) must be properly escaped using the new utility function before being included in translated strings.
- **AC4 (error message localized)**: The hardcoded error message in the global error handler (`src/bot/bot.py`) must be moved into the localization files and translated for all supported languages.
- **AC5 (locales markdown-v2 review)**: All localization files (`src/locales/*.yaml`) must be reviewed and updated to ensure their syntax is compatible with MarkdownV2. Special characters intended for formatting must be correct, and literal characters must be escaped.
- **AC6 (app functions without formatting errors)**: The application must function correctly with the new parsing mode, and there should be no message formatting errors.

### Refactoring Performed
A minor bug was identified and fixed in the global error handler to bring it into compliance with localization best practices.

- **File**: `src/bot/bot.py`
  - **Change**: Modified the `error_handler` to dynamically infer the user's locale from the update context instead of using a hardcoded `'en'` locale.
  - **Why**: To ensure that generic error messages are correctly localized according to the user's language preference.
  - **How**: The handler now inspects `update.effective_user.language_code`, normalizes it, and falls back to the default locale if the user-specific locale cannot be determined.
