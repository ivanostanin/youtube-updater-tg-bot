# Story 1.14: Localize Telegram User Messages

## Status

Ready for Review

---

## Story

**As a** multilingual Telegram chat administrator,  
**I want** all bot commands, prompts, and notifications to respect my chat’s preferred language,  
**so that** moderators and subscribers who do not speak English can still manage subscriptions confidently.

---

## Acceptance Criteria

1. **AC1 (Localization framework & catalogs):** Add a centralized i18n helper (e.g., `src/utils/i18n.py`) that loads translation dictionaries for `en`, `ru`, and `de` from UTF-8 resource files (such as `locales/<lang>.yaml`), exposes `translate(key, locale, **kwargs)` with printf-style placeholders, and falls back to English with a single WARN per request when a key is missing. Catalog coverage must replace every user-facing string currently hard-coded in `src/bot/handlers.py`, `src/bot/notifications.py`, and `src/utils/formatters.py`, and keep emoji/Markdown escaping intact. *(Sources: docs/architecture/8-source-tree.md §Existing Project Structure; src/bot/handlers.py; src/bot/notifications.py; src/utils/formatters.py)*
2. **AC2 (Locale preference storage & selection):** Extend the `chats` table/model/repository with a `preferred_locale` column (nullable, <=5 chars) plus Alembic migration, add `DEFAULT_LOCALE`/`default_locale` to `.env.example` and `src/utils/config.py`, hydrate new chats from `Update.effective_user.language_code` when it matches a supported language, and implement a `/language` command with inline keyboard buttons for `English (en)`, `Русский (ru)`, `Deutsch (de)` that persists the choice via `ChatRepository`. Responses confirming the change must be localized. *(Sources: src/database/models.py; src/database/repository.py; src/utils/config.py; src/bot/handlers.py; docs/architecture/5-component-architecture.md §PreferenceManager; docs/prd/2-requirements.md §FR3 Bot Commands)*
3. **AC3 (Localized bot command flows):** All replies produced by `BotHandlers`—including `/start`, `/help`, `/subscribe` argument validation, `/list`, `/unsubscribe` (plus inline keyboard labels), `handle_unsubscribe_callback`, `_require_admin` denials, and private chat nudges in `handle_message`—must fetch the chat’s locale (with fallback) and render text through the i18n helper. English literals should exist only inside translation resources, and unknown locales must downgrade gracefully without breaking Markdown. *(Sources: src/bot/handlers.py; docs/architecture/10-coding-standards.md §Existing Standards)*
4. **AC4 (Localized notifications & formatting):** Update `NotificationService` (`format_video_message`, `send_subscription_confirmation`, `send_error_notification`) and `src/utils/formatters.py` helpers to accept a locale argument, render translated labels (including date/time strings and inline prompts) using the helper, and ensure `WebhookHandlers.process_video_update` passes each subscriber chat’s stored locale when dispatching `send_video_notification`. Fallback behavior must always default to English while logging once when translation data is missing. *(Sources: src/bot/notifications.py; src/utils/formatters.py; src/webhooks/handlers.py; docs/prd/2-requirements.md §FR6 Notifications)*
5. **AC5 (Documentation & automated coverage):** Document localization support and `/language` usage in `.env.example`, `README.md`, and `CLAUDE.md`, including how unsupported Telegram language codes map to the default locale. Add/extend pytest coverage (`tests/unit/test_handlers.py`, `tests/unit/test_notifications.py`, `tests/unit/test_formatters.py`, and an integration flow) to assert locale persistence, translation fallback, and localized webhook notifications; ensure these tests run under the existing CI job. *(Sources: docs/architecture/11-testing-strategy.md; docs/stories/1.3.setup-comprehensive-test-suite.md; README.md)*

## Dev Notes

- **Message inventory:** All user-facing strings live today in `src/bot/handlers.py`, `src/bot/notifications.py`, and `src/utils/formatters.py` (see docs/architecture/8-source-tree.md). Audit these modules first so translation keys match real usage and remain Markdown-safe.  
- **Preference storage:** Architecture section 5 (§PreferenceManager) already anticipates per-chat settings. Extending the `chats` table with `preferred_locale` keeps the scope brownfield and avoids introducing a brand-new preferences table.  
- **Telegram metadata:** `python-telegram-bot` exposes `Update.effective_user.language_code`, but values may include region suffixes (`en-US`). Normalize by splitting on `-`/`_` and only persisting codes defined in the catalog; otherwise use `settings.default_locale`.  
- **Notification pipeline:** `WebhookHandlers.process_video_update()` currently has access to `subscription.chat`; use that to fetch locale before calling `NotificationService`. Make sure repository eager loading still works when accessing the new column.  
- **Config validation:** Keep `settings.default_locale` limited to the supported set so env misconfiguration surfaces early (raise `ValueError` during Settings instantiation).  
- **Docs references:** Align README + CLAUDE instructions with existing coding/testing standards (`docs/architecture/10-coding-standards.md`, `docs/architecture/11-testing-strategy.md`) so dev agents know where to place tests and how to run them.

## Testing

### Testing Expectations

- Follow the pytest structure and Allure tagging defined in `docs/architecture/11-testing-strategy.md` and `docs/stories/1.3.setup-comprehensive-test-suite.md`.  
- Add unit tests for the new i18n helper (fallbacks, formatting), `/language` handler paths (`tests/unit/test_handlers.py`), and NotificationService/formatter output (`tests/unit/test_notifications.py`, `tests/unit/test_formatters.py`).  
- Create/extend integration coverage (e.g., `tests/integration/test_bot_flow.py` or webhook-focused tests) to assert that a stored `preferred_locale` drives localized notifications end-to-end.

### Observability & Metrics

- Reuse the structured logging approach from Story 1.11 (debug logging instrumentation) so locale selections and fallback warnings include `request_id`, `chat_id`, and sanitized metadata.  
- Emit at most one WARN per request when falling back to the default locale to avoid log noise. Consider a counter/metric (e.g., `localization_fallback_total`) if monitoring is desired later.

### Risks & Constraints

- **Incomplete catalogs:** Missing translation keys degrade UX; keep tests that fail when catalogs omit required keys.  
- **Markdown safety:** Translated strings may introduce underscores or brackets—escape them before sending to Telegram to avoid formatting issues.  
- **Group governance:** Changing the language in a group/channel should respect ACL requirements so non-admins cannot override preferences for everyone.

### Definition of Done

- All acceptance criteria satisfied with passing CI (`pytest --alluredir=allure-results`).  
- Localization helper + catalogs validated by automated tests, with fallback warnings only when expected.  
- `/language` command demoed in private and group chats (admin + non-admin scenarios).  
- README, CLAUDE, and `.env.example` updated; story moved to “Ready for Dev” once scope/tasks/notes are complete.
