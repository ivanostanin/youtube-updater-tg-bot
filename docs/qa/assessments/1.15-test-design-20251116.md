# Test Design: Story 1.15

Date: 2025-11-16
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 17
- Unit tests: 8 (47%)
- Integration tests: 8 (47%)
- E2E tests: 1 (6%)
- Priority distribution: P0: 7, P1: 8, P2: 2

## Test Scenarios by Acceptance Criteria

### AC1: Channel linking over DM

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.15-UNIT-001 | Unit | P1 | `/channel_link` argument parser normalizes usernames, numeric chat IDs, and rejects non-DM contexts before any Telegram calls. | Pure validation logic; keeps handler fast and prevents noisy API calls. |
| 1.15-INT-001 | Integration | P0 | Happy-path `/channel_link` DM prompts for channel, verifies admin via `getChatMember`, upserts the `chats` row with `chat_type='channel'`, and returns localized confirmation. | Requires handler ↔ Telegram client ↔ repository wiring to satisfy AC1. |
| 1.15-INT-002 | Integration | P0 | Non-admin (or admin removed from channel) receives denial copy, no DB mutations occur, and a structured audit log is emitted. | Security-critical rejection that depends on live Telegram responses and persistence guardrails. |

### AC2: Per-channel configuration context

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.15-UNIT-002 | Unit | P1 | Channel-context manager associates `admin_user_id` → `channel_chat_id`, persists TTL, and clears context when a link is revoked or expires. | State transitions can be validated without I/O to prevent context confusion. |
| 1.15-INT-003 | Integration | P1 | `/channel_select` renders inline keyboard rows from `channel_admin_links`, stores active context, and acknowledges selection mentioning the channel title. | Exercises DM UI + repository cooperation demanded by AC2. |
| 1.15-INT-004 | Integration | P0 | After selecting a channel, `/subscribe`, `/unsubscribe`, `/list`, and `/options` mutate/read the linked channel chat_id instead of the admin’s DM, and responses clearly state the target channel. | Core behavioral change that drives all downstream automation; must be verified end-to-end at handler level. |

### AC3: Channel-bound notification dispatch

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.15-INT-005 | Integration | P0 | Subscriptions created while a channel context is active cause NotificationService and PubSub/webhook handlers to enqueue messages to the stored channel chat_id with channel-safe Markdown (no @user callouts). | Confirms the notification pipeline respects the per-channel routing data. |
| 1.15-E2E-001 | E2E | P0 | Full DM journey: link channel → select it → subscribe to a feed → receive a channel broadcast with attribution and localized admin reminder, while administrative prompts stay private. | Validates IV1–IV4 in a realistic environment and ensures DM-only onboarding behaves coherently. |

### AC4: Access control & auditing

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.15-UNIT-003 | Unit | P1 | `ChannelAdminLinkRepository` enforces unique `(channel_chat_id, admin_user_id)` pairs, captures `role`, `linked_at`, `revoked_at`, and exposes helpers for auditing queries. | Data-model validation that prevents duplicate links and preserves audit history. |
| 1.15-INT-006 | Integration | P0 | When Telegram reports an admin no longer has privileges (via `getChatMember` or webhook), the system marks the link revoked, blocks `/channel_select`, and emits `ChannelAdminRevoked` logs with `chat_id`/`user_id`. | Directly enforces AC4 revocation + logging requirements and mitigates permission drift risk. |
| 1.15-UNIT-008 | Unit | P1 | Audit/logging helper redacts invite links and PII before persisting structured ACL events. | Guards against the “Security exposure” risk without requiring external systems. |

### AC5: Operator UX & documentation

| --- | --- | --- | --- | --- |

| 1.15-UNIT-005 | Unit | P2 | Documentation sync test asserts `.env.example`, `README.md`, and `CLAUDE.md` include the DM-only channel flow, permission checklist, and troubleshooting guidance. | Lightweight content guard preventing AC5 regressions in CI. |

### AC6: Test coverage & monitoring

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.15-UNIT-006 | Unit | P1 | Instrumentation helper emits `LinkChannelSuccess`, `ChannelSelectionDenied`, and `ChannelDelivery` metrics/log counters with structured dimensions (`chat_type`, `user_id`). | Ensures observability contracts exist before integration tests rely on them. |
| 1.15-INT-007 | Integration | P1 | Pytest suite (executed via `uv run pytest`) covers channel linking, selection, ACL enforcement, and notification dispatch flows while asserting the expected metrics/log entries. | Verifies AC6’s CI requirement and that instrumentation survives real flows. |

### AC7: Bot permission verification

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.15-INT-008 | Integration | P0 | `/channel_link` double-checks the bot’s membership via `getChatMember(bot_id, channel)` and blocks linking unless `can_post_messages` (and other required flags) are true, returning localized remediation steps. | Prevents unusable channel links and enforces AC7’s permission gate. |
| 1.15-UNIT-007 | Unit | P1 | Permission evaluation helper compares Telegram permission payloads against required capabilities and produces human-readable remediation copy. | Keeps the integration test simple while guaranteeing consistent validation logic. |

## Risk Coverage

- **Telegram permission drift** is mitigated by scenarios 1.15-INT-006, 1.15-INT-008, and 1.15-UNIT-007 that continuously re-verify admin + bot permissions and block stale contexts.
- **Context confusion** is handled by 1.15-UNIT-002 and 1.15-INT-003/004, which keep channel selection explicit and reset contexts when stale.
- **Security exposure of channel data** is contained via 1.15-INT-002, 1.15-UNIT-003, and 1.15-UNIT-008 that enforce ACLs and redact sensitive metadata.
- **Observability blind spots** are reduced by 1.15-UNIT-006 and 1.15-INT-007, guaranteeing telemetry around linking, selection, and delivery volumes.

## Recommended Execution Order

1. Run P0/P1 unit guards (`1.15-UNIT-001`, `1.15-UNIT-002`, `1.15-UNIT-003`, `1.15-UNIT-006`, `1.15-UNIT-007`) to fail fast on parsing, context, data-model, and metrics regressions.
2. Execute security-sensitive integrations (`1.15-INT-001/002/006/008`) to confirm linking, ACL enforcement, and permission gating work before more expensive flows.
3. Cover channel context command journeys (`1.15-INT-003/004`) followed by notification routing (`1.15-INT-005`) and observability assertions (`1.15-INT-007`).
4. Validate documentation and UX helpers (`1.15-UNIT-004/005`) once core behavior stabilizes.
5. Finish with the full end-to-end scenario (`1.15-E2E-001`) to prove DM-only onboarding through channel broadcast delivery.
