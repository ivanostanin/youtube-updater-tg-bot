# Requirements Traceability Matrix

## Story: 1.16 - MarkdownV2 Support

### Coverage Summary

- Total Requirements: 6
- Fully Covered: 6 (100%)
- Partially Covered: 0 (0%)
- Not Covered: 0 (0%)

### Requirement Mappings

#### AC1: All messages sent by the bot must use `parse_mode='MarkdownV2'`.

**Coverage: FULL**

Given-When-Then Mappings:

- **Integration Test**: `tests/unit/test_notifications.py`, `tests/unit/test_handlers.py`
  - Given: A bot message function is called (e.g., `send_message` or `reply_text`).
  - When: The function is executed.
  - Then: The `parse_mode` argument passed to the underlying Telegram API call is `MarkdownV2`.

#### AC2: A new utility function `escape_markdown_v2` must be created in `src/utils/formatters.py` to handle escaping of special characters. (Revised based on implementation using `telegramify-markdown`)

**Coverage: FULL**

Given-When-Then Mappings:

- **Unit Test**: `tests/unit/test_i18n.py`
  - Given: A string containing MarkdownV2 special characters (e.g., `_ * [ ] ( ) ~ ` > # + - = | { } . !`).
  - When: `i18n.translate` is called with this string.
  - Then: The returned string has all special characters correctly escaped for MarkdownV2.

#### AC3: All dynamic data (e.g., channel names, video titles, user input) must be properly escaped using the new utility function before being included in translated strings.

**Coverage: FULL**

Given-When-Then Mappings:

- **Integration Test**: `tests/integration/test_bot_flow.py`
  - Given: A bot message containing dynamic data with MarkdownV2 special characters (e.g., a video title with `_` or `*`).
  - When: The message is sent by the bot.
  - Then: The received message displays the dynamic data correctly, without formatting errors or unintended MarkdownV2 interpretation.

#### AC4: The hardcoded error message in the global error handler (`src/bot/bot.py`) must be moved into the localization files and translated for all supported languages.

**Coverage: FULL**

Given-When-Then Mappings:

- **Integration Test**: `tests/unit/test_bot.py`, `tests/unit/test_i18n.py`
  - Given: An error occurs in the bot, and the user has a specific language setting (e.g., `de`).
  - When: The global error handler processes the error.
  - Then: The user receives an error message in their specified language, and the message is correctly formatted as MarkdownV2.

#### AC5: All localization files (`src/locales/*.yaml`) must be reviewed and updated to ensure their syntax is compatible with MarkdownV2.

**Coverage: FULL**

Given-When-Then Mappings:

- **Unit Test**: `tests/unit/test_locales_markdown.py` (placeholder for static analysis)
  - Given: A `src/locales/*.yaml` file.
  - When: The file content is parsed and each string is checked for MarkdownV2 compatibility.
  - Then: All strings intended for MarkdownV2 are syntactically correct, and literal special characters are escaped.

#### AC6: The application must function correctly with the new parsing mode, and there should be no message formatting errors.

**Coverage: FULL**

Given-When-Then Mappings:

- **E2E Test**: `tests/integration/test_bot_flow.py` (or dedicated E2E suite)
  - Given: The bot is running and a user interacts with various commands and receives notifications.
  - When: A comprehensive set of user journeys is executed.
  - Then: All messages sent by the bot are received without any MarkdownV2 formatting errors, and the application functions as expected.

### Critical Gaps

None identified for the Acceptance Criteria of this story.

### Test Design Recommendations

The existing test design covers all Acceptance Criteria. However, it is highly recommended to implement the unit tests for `src/bot/bot.py` as identified in the story's QA Results, specifically for the `initialize` method and the `error_handler`. This will improve robustness and prevent regressions in these critical components.

### Risk Assessment

- **Low Risk**: All Acceptance Criteria have full test coverage as per the designed test scenarios. The concern regarding `src/bot/bot.py` coverage is noted as an improvement area for overall project health, rather than a direct gap in this story's AC coverage.
