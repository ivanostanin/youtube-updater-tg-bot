### Critical Gaps

1. **AC3 – Localized bot commands**  
   - Gap: No tests assert that core commands and ACL flows render localized text or respect stored locales.  
   - Risk: High – regressions would directly impact every user interaction.  
   - Recommended Test: Add unit/integration tests for `/start`, `/help`, `/subscribe`, `/list`, `/unsubscribe`, `_require_admin`, and `handle_message` covering both default and overridden locales.

2. **AC1 – Catalog completeness guard**  
   - Gap: No automation verifies that translation catalogs include every key referenced in code.  
   - Risk: Medium – missing keys silently fall back to English.  
   - Recommended Test: Implement a unit test or CI script that walks `src/bot/handlers.py`, `src/bot/notifications.py`, `src/utils/formatters.py` (and others) and fails if translation keys are absent from each locale file.

3. **AC5 – Documentation drift guard**  
   - Gap: Docs now describe fallback behavior, but there is no automated check to ensure future changes stay aligned.  
   - Risk: Low – drift is unlikely but still possible without CI enforcement.  
   - Recommended Action: Add a lightweight doc-sync test (or lint rule) that verifies the fallback note exists across `.env.example`, `README.md`, and `CLAUDE.md`.

### Test Design Recommendations

1. Expand handler-level unit tests to cover localized outputs for every command listed in AC3, asserting both default_locale and a non-English locale to catch regressions early.
2. Add a small contract test that iterates over all locale YAML files and ensures every key used by `translate()` in the codebase exists for `en/ru/de`, preventing silent fallbacks.
3. Create an integration/E2E test that exercises the `/language` command followed by a subscribe/unsubscribe flow to prove that subsequent notifications and inline keyboards respect the updated locale.

### Risk Assessment

- **Medium Risk:** AC3 lacks non-English handler tests, so locale override regressions might slip through CI.  
- **Medium Risk:** Catalog completeness and documentation gaps increase the chance of inconsistent user experiences.  
- **Low Risk:** Notification/webhook locale propagation has both unit and integration coverage.
