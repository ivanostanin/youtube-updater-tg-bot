# Test Design: Story 1.14

Date: 2025-11-16
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 16
- Unit tests: 8 (50%)
- Integration tests: 6 (38%)
- E2E tests: 2 (12%)
- Priority distribution: P0: 4, P1: 10, P2: 2

## Test Scenarios by Acceptance Criteria

### AC1: Localization framework & catalogs

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.14-UNIT-001 | Unit | P1 | `translate` returns locale-specific strings with printf placeholders and preserves emoji/Markdown characters. | Pure helper logic; fastest place to validate formatting before handlers rely on it. |
| 1.14-UNIT-002 | Unit | P0 | Missing keys fall back to English exactly once per request while emitting a structured WARN. | Prevents untranslated output in production and enforces noise-free logging. |
| 1.14-UNIT-003 | Unit | P1 | Unsupported locale inputs (e.g., `es`, `en-US`) normalize to the configured default locale. | Guarantees graceful downgrade without duplicating logic in callers. |
| 1.14-UNIT-004 | Unit | P0 | Catalog-completeness guard that fails when handlers/notifications reference keys absent from any locale file. | Detects incomplete translations early, mitigating the “incomplete catalogs” risk. |

### AC2: Locale preference storage & selection

| 1.14-UNIT-008 | Unit | P2 | Doc/config sync check ensures `.env.example`, `README.md`, and `CLAUDE.md` mention `DEFAULT_LOCALE` and locale mapping guidance. | Lightweight guard so documentation drifts surface during CI. |

## Risk Coverage

- **Incomplete catalogs:** Mitigated by 1.14-UNIT-004 and localized handler tests (1.14-INT-004/005) that fail when keys are absent.
- **Markdown safety:** Addressed by 1.14-UNIT-001/006 and 1.14-INT-004 which assert escaped output regardless of locale characters.
- **Fallback noise:** 1.14-UNIT-002/007 verify WARN frequency control to avoid log flooding when translations are missing.
- **Unauthorized locale changes:** 1.14-INT-003 ensures ACL enforcement for `/language` in shared chats.
- **End-to-end locale drift:** 1.14-INT-006 and 1.14-E2E-002 confirm the stored locale propagates through webhook notifications.

## Recommended Execution Order

1. Run P0 unit guards (1.14-UNIT-002, 1.14-UNIT-004) to fail fast on catalog/fallback regressions.
2. Execute repository/config unit + integration tests (1.14-INT-001, 1.14-UNIT-005, 1.14-INT-002/003) to validate locale persistence before wiring handlers.
3. Cover handler-level integrations (1.14-INT-004/005) followed by NotificationService units (1.14-UNIT-006/007).
4. Run webhook + notification integrations (1.14-INT-006) before full E2E suites (1.14-E2E-001/002).
5. Finish with documentation sync check (1.14-UNIT-008) once behavior is stable.
