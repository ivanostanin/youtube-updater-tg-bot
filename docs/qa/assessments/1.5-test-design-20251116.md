## Risk Coverage

- **Performance Noise / Blocking Gauges** – Covered by 1.5-INT-006 to ensure gauges refresh asynchronously and remain lightweight under webhook load.
- **Secrets or PII Leakage in Logs** – 1.5-UNIT-002 and 1.5-INT-008 assert structured logs contain only approved context fields.
- **Collector Duplication Between Test Runs** – 1.5-UNIT-001 fixture setup clears registries, preventing duplicate metric registration regressions.
- **Kubernetes Probe Drift** – 1.5-INT-011 validates Helm templates so probes and annotations cannot regress silently during chart edits.

## Recommended Execution Order

1. Critical P0 unit coverage (1.5-UNIT-002) followed by Prometheus helper validation (1.5-UNIT-001).
2. Core integration flows powering monitoring stack (1.5-INT-001, 1.5-INT-003, 1.5-INT-007, 1.5-INT-008, 1.5-INT-009, 1.5-INT-011).
3. Remaining P1 integration scenarios (1.5-INT-002, 1.5-INT-004, 1.5-INT-005, 1.5-INT-006, 1.5-INT-010).
4. Documentation/observability artifact checks (1.5-UNIT-003, 1.5-UNIT-004).

## Coverage Gaps & Notes

- Alert rules for the new metrics are out of scope; recommend future work to add automated alert validation once alertmanager integration lands.
- Helm test relies on `helm template`; ensure CI environment has Helm binary and Kubernetes schema validation (e.g., `kubeconform`) to maximize signal.
- Dashboard validation currently checks references only; consider snapshot-testing rendered Grafana panels once a headless Grafana exporter is available.
