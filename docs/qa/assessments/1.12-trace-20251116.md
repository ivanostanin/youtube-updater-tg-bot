# Requirements Traceability Matrix

## Story: 1.12 - Auto-Renew PubSub Hub Leases

### Coverage Summary

- Total Requirements: 5
- Fully Covered: 4 (80%)
- Partially Covered: 1 (20%)
- Not Covered: 0 (0%)

### Requirement Mappings

#### AC1: Webhook lease metadata capture and unsubscribe clearing

**Coverage: FULL (unit)**

- `tests/unit/test_webhook_handlers.py::test_webhook_handler_stores_lease_metadata`
  - Given: an existing channel and a subscribe verification request without `hub.lease_seconds`
  - When: the handler processes the challenge
  - Then: it persists the callback URL, default lease seconds, and expiry timestamp on the channel row
- `tests/unit/test_webhook_handlers.py::test_webhook_handler_clears_metadata_on_unsubscribe`
  - Given: a channel populated with prior lease metadata
  - When: an unsubscribe challenge arrives for that channel
  - Then: the handler clears all lease fields before echoing the challenge response

#### AC2: Schema, backfill, and repository helpers for lease metadata

**Coverage: FULL (unit)**

- `tests/unit/test_repository.py::test_channel_repository_webhook_metadata_crud`
  - Given: a created channel
  - When: `record_webhook_verification` is called with lease data and later `clear_webhook_metadata`
  - Then: the repository writes and clears the new columns as expected
- `tests/unit/test_repository.py::test_channel_repository_returns_lease_candidates`
  - Given: a channel with an expiring lease and an active subscriber
  - When: the renewal query runs with a threshold inside the expiry window
  - Then: the channel is surfaced as a candidate and disappears once expiry is beyond the threshold
- `tests/unit/test_migration_backfill.py::test_backfill_uses_most_recent_subscription_webhook`
  - Given: multiple historical subscriptions with different webhook URLs
  - When: `_backfill_callback_urls` executes
  - Then: it copies the most recent non-null webhook into `youtube_channels.webhook_callback_url`

#### AC3: Automatic lease refresh service

**Coverage: FULL (unit)**

- `tests/unit/test_webhook_lease_refresher.py::test_lease_refresher_renews_candidates`
  - Given: a channel with an expiring lease and an active subscriber
  - When: the refresher runs within the renewal threshold
  - Then: it calls `PubSubManager.subscribe_to_channel`, updates lease metadata, and records the callback URL
- `tests/unit/test_webhook_lease_refresher.py::test_lease_refresher_skips_when_no_candidates`
  - Given: channels whose leases expire outside the renewal window
  - When: the refresher executes
  - Then: it exits without invoking the PubSub manager, confirming the guard against unnecessary renewals

#### AC4: Guardrails for inactive subscriptions and cleanup on last unsubscribe

**Coverage: PARTIAL (unit)**

- `tests/unit/test_repository.py::test_subscription_repository_channel_has_active_subscribers`
  - Given: a channel with mixed active/inactive subscriptions
  - When: the repository checks for active subscribers (optionally excluding a chat)
  - Then: it returns True only when at least one notification-enabled subscriber remains
- **Gap**: No automated test covers the end-to-end path where the unsubscribe flow clears metadata and issues a `hub.mode=unsubscribe` when the final subscriber leaves (verification handler tests only cover hub-originated unsubscribes).

#### AC5: Observability, configuration defaults, and tests

**Coverage: FULL (unit)**

- `tests/unit/test_config.py::{test_pubsub_settings_defaults,test_pubsub_settings_validation}`
  - Given: environment overrides and defaults
  - When: `Settings()` loads
  - Then: it enforces sane defaults, positive intervals, and validation errors for invalid inputs
- `tests/unit/test_webhook_handlers.py::{test_webhook_handler_stores_lease_metadata,test_webhook_handler_clears_metadata_on_unsubscribe}`
  - Given: subscribe/unsubscribe verification flows
  - When: the handler processes challenges
  - Then: it persists or clears lease metadata and increments Prometheus counters per mode/result
- `tests/unit/test_webhook_lease_refresher.py::{test_lease_refresher_renews_candidates,test_lease_refresher_skips_when_no_candidates}`
  - Given: expiring/non-expiring channels
  - When: the refresher job runs
  - Then: it records appropriate metrics labels (`attempt`, `success`, `skipped`) alongside lease persistence

### Critical Gaps

1. **Unsubscribe guardrails (AC4)**
   - Gap: Missing integration/unit coverage for the bot workflow that issues a best-effort `hub.mode=unsubscribe` and clears metadata when the last subscriber leaves.
   - Risk: Medium – lingering leases could keep traffic flowing to disabled chats.

### Test Design Recommendations

1. Create an integration/unit test for the unsubscribe handler path that simulates the final subscriber removal and verifies PubSub unsubscribe + metadata clearing.

### Risk Assessment

- **High Risk**: None identified during tracing.
- **Medium Risk**: AC4 gap above – still desirable before sign-off, but mitigated by repository/unit coverage elsewhere.
- **Low Risk**: AC1, AC2, AC3, AC5 – covered by deterministic unit tests and aligned with logging standards.
