### Critical Gaps

1. **Migration backfill accuracy (AC2)**
   - Gap: No tests ensure the Alembic backfill selects the most recent non-null webhook URL per channel or behaves consistently across databases.
   - Risk: Medium – stale callback URLs can block renewals until manual fixes.
2. **Unsubscribe guardrails (AC4)**
   - Gap: Missing integration/unit coverage for the bot workflow that issues a best-effort `hub.mode=unsubscribe` and clears metadata when the last subscriber leaves.
   - Risk: Medium – lingering leases could keep traffic flowing to disabled chats.
3. **Observability metrics (AC5)**
   - Gap: Metrics instrumentation and verification are absent, so operators cannot alert on lease churn/failures.
   - Risk: Medium – failures may go unnoticed until subscribers report missing notifications.

### Test Design Recommendations

1. Add migration-focused tests (or scripts) that seed multiple webhook URLs per channel, run the Alembic upgrade on SQLite/PostgreSQL, and assert the latest URL wins.
2. Create an integration/unit test for the unsubscribe handler path that simulates the final subscriber removal and verifies PubSub unsubscribe + metadata clearing.
3. Introduce Prometheus (or existing metrics stack) counters/gauges for lease verifications, renew attempts, successes, failures, and skips; add unit tests that assert increments via dependency injection/mocking.

### Risk Assessment

- **High Risk**: None identified during tracing.
- **Medium Risk**: AC2, AC4, AC5 gaps as detailed above – block "Ready for Done" until addressed.
- **Low Risk**: AC1 and AC3 – covered by deterministic unit tests and aligned with logging standards.
