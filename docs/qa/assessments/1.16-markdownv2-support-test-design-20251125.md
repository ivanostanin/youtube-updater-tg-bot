# Test Design: Story 1.16

Date: 2025-11-25
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 6
- Unit tests: 2 (33%)
- Integration tests: 3 (50%)
- E2E tests: 1 (17%)
- Priority distribution: P0: 4, P1: 2

## Test Scenarios by Acceptance Criteria

### AC1: All messages sent by the bot must use `parse_mode='MarkdownV2'`.

#### Scenarios

| ID           | Level       | Priority | Test                      | Justification                                         |
| ------------ | ----------- | -------- | ------------------------- | ----------------------------------------------------- |
| 1.16-INT-001 | Integration | P0       | Verify `parse_mode='MarkdownV2'` in message sending functions | Ensures the core requirement of the story is met across all message outputs. It needs to interact with the bot's sending mechanism. |

### AC2: A new utility function `escape_markdown_v2` must be created in `src/utils/formatters.py` to handle escaping of special characters. (Revised based on implementation using `telegramify-markdown`)

#### Scenarios

| ID           | Level | Priority | Test                      | Justification                                         |
| ------------ | ----- | -------- | ------------------------- | ----------------------------------------------------- |
| 1.16-UNIT-001 | Unit  | P0       | Test `i18n.translate` with MarkdownV2 special characters for correct escaping | Pure logic/algorithm test for escaping. Ensures the utility handles all special characters as expected, preventing message parsing errors and potential injection vulnerabilities. |

### AC3: All dynamic data (e.g., channel names, video titles, user input) must be properly escaped using the new utility function before being included in translated strings.

#### Scenarios

| ID           | Level       | Priority | Test                      | Justification                                         |
| ------------ | ----------- | -------- | ------------------------- | ----------------------------------------------------- |
| 1.16-INT-002 | Integration | P0       | Verify dynamic data in messages is correctly escaped and rendered without MarkdownV2 errors | This tests the interaction between data retrieval, escaping logic, and message sending. |

### AC4: The hardcoded error message in the global error handler (`src/bot/bot.py`) must be moved into the localization files and translated for all supported languages.

#### Scenarios

| ID           | Level       | Priority | Test                      | Justification                                         |
| ------------ | ----------- | -------- | ------------------------- | ----------------------------------------------------- |
| 1.16-INT-003 | Integration | P1       | Trigger bot error and verify localized, MarkdownV2-rendered error message | Tests the end-to-end flow of error handling and localization. The story's QA results even indicate a bug here that was fixed. |

### AC5: All localization files (`src/locales/*.yaml`) must be reviewed and updated to ensure their syntax is compatible with MarkdownV2.

#### Scenarios

| ID           | Level | Priority | Test                      | Justification                                         |
| ------------ | ----- | -------- | ------------------------- | ----------------------------------------------------- |
| 1.16-UNIT-002 | Unit  | P1       | Validate MarkdownV2 syntax in `src/locales/*.yaml` files | This can be a static test of the YAML content without needing the bot to send messages. It ensures the source content is correct. |

### AC6: The application must function correctly with the new parsing mode, and there should be no message formatting errors.

#### Scenarios

| ID           | Level | Priority | Test                      | Justification                                         |
| ------------ | ----- | -------- | ------------------------- | ----------------------------------------------------- |
| 1.16-E2E-001 | E2E   | P0       | Execute full suite of bot commands/notifications to ensure no formatting errors | This is the ultimate validation that the entire system works as expected with the new formatting mode. |

## Risk Coverage

The test scenarios cover the primary risks associated with MarkdownV2 adoption: inconsistent parsing mode enforcement, incorrect escaping of dynamic data, broken localization due to formatting, and general application instability. Specific attention was paid to the previously identified bug in the error handler localization.

## Recommended Execution Order

1. P0 Unit tests (fail fast)
2. P0 Integration tests
3. P0 E2E tests
4. P1 tests in order
5. P2+ as time permits
