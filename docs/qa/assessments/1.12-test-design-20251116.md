# Test Design: Story 1.12

Date: 2025-11-16  
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 13
- Distribution by level: Unit 5 (38%), Integration 6 (46%), E2E 2 (16%)
- Priority distribution: P0 6, P1 6, P2 1, P3 0
- Focus areas: capture/clearing webhook lease metadata, schema + repository fidelity, reliable auto-renewal workflow, and guardrails to prevent unwanted renewals

## Test Scenarios by Acceptance Criteria

### AC1: Webhook lease metadata capture

| ID | Level | Priority | Test | Justification / Risks |
| --- | --- | --- | --- | --- |
| 1.12-UNIT-001 | Unit | P0 | Validate parsing of `hub.topic`, derivation of `channel_id`, and calculation of `lease_expires_at` using the request timestamp plus provided `hub.lease_seconds`, while echoing `hub.challenge`. | Pure logic that, if wrong, silently expires leases (RISK-001). |
| 1.12-UNIT-002 | Unit | P1 | When `hub.lease_seconds` is missing, ensure handler defaults to 86 400 seconds, emits a WARN log with structured context, and still persists metadata. | Keeps telemetry trustworthy even when hubs omit leases (RISK-001, RISK-006). |
| 1.12-UNIT-003 | Unit | P0 | `hub.mode=unsubscribe` path only clears metadata for the derived channel and does not affect other records while still echoing `hub.challenge`. | Prevents cross-channel data loss and ensures clean shutdowns (RISK-002). |
| 1.12-INT-001 | Integration | P0 | Full request→response cycle persists lease metadata (callback URL, lease_seconds, expires_at UTC, last_verified_at) via `ChannelRepository` and commits before returning HTTP 200. | Confirms DB contract and prevents silent failures (RISK-001). |

### AC2: Schema & repository support

| ID | Level | Priority | Test | Justification / Risks |
| --- | --- | --- | --- | --- |
| 1.12-INT-002 | Integration | P0 | Alembic migration adds the four lease columns, is idempotent across SQLite/PostgreSQL, and backfills from `Subscription.webhook_url` (or settings fallback) without null regressions. | Guarantees schema parity across environments (RISK-003). |
| 1.12-INT-003 | Integration | P1 | Repository projector `channels_ready_for_lease_renewal` returns only channels with active subscribers, `notification_enabled=True`, and `lease_expires_at` <= threshold or NULL. | Ensures auto-renew job sees accurate candidates (RISK-004, RISK-005). |

### AC3: Automatic lease refresh service

| ID | Level | Priority | Test | Justification / Risks |
| --- | --- | --- | --- | --- |
| 1.12-INT-004 | Integration | P0 | `WebhookLeaseRefresher` selects expiring channels, calls `PubSubManager.subscribe_to_channel`, persists the renewed lease metadata, and logs structured context (`channel_id`, seconds granted, next expiry). | Core renewal happy path; failure leads to service outage (RISK-004). |
| 1.12-INT-005 | Integration | P1 | Simulate PubSub manager failure; refresher emits ERROR log, increments retry/metric counters, and schedules the next attempt without crashing the job queue worker. | Ensures resilience and observability on failures (RISK-004, RISK-006). |

### AC4: Inactive subscription guardrails

| ID | Level | Priority | Test | Justification / Risks |
| --- | --- | --- | --- | --- |
| 1.12-UNIT-004 | Unit | P1 | Guard clauses skip renewal when all related subscriptions are inactive or `notification_enabled=False`, even if lease expiry is near. | Prevents resurrecting intentionally disabled channels (RISK-005). |
| 1.12-INT-006 | Integration | P1 | When the last active subscription is removed, the system clears stored lease metadata and issues best-effort `hub.mode=unsubscribe` exactly once. | Avoids leaking active leases and cleans up hub traffic (RISK-002, RISK-005). |

### AC5: Observability, configuration, and tests

| ID | Level | Priority | Test | Justification / Risks |
| --- | --- | --- | --- | --- |
| 1.12-UNIT-005 | Unit | P2 | Validate configuration loader recognizes `PUBSUB_LEASE_RENEWAL_INTERVAL` and `PUBSUB_LEASE_RENEWAL_THRESHOLD`, applies sane defaults, and exposes them to the refresher/job queue. | Prevents misconfiguration-driven outages (RISK-006). |

### Cross-AC End-to-End Regression

| ID | Level | Priority | Test | Justification / Risks |
| --- | --- | --- | --- | --- |
| 1.12-E2E-001 | E2E | P0 | Simulate a full handshake + renewal: webhook subscribe request stores metadata, clock advances near expiry, refresher runs via Telegram `job_queue`, PubSub stub issues renewed lease, metrics/logs capture success. | Validates the user-visible promise that leases never lapse (RISK-001, RISK-004). |
| 1.12-E2E-002 | E2E | P1 | Channel with `notification_enabled=False` receives unsubscribe, metadata cleared, and refresher job confirms the channel is skipped on subsequent runs while hub unsub call occurs. | Ensures guardrails work in production-like flows (RISK-005). |

## Risk Coverage

- **RISK-001 – Silent lease expiry because metadata not captured/renewed:** Mitigated by 1.12-UNIT-001, 1.12-UNIT-002, 1.12-INT-001, 1.12-INT-004, 1.12-E2E-001.
- **RISK-002 – Clearing the wrong channel’s lease metadata:** Mitigated by 1.12-UNIT-003, 1.12-INT-006.
- **RISK-003 – Schema divergence between environments:** Mitigated by 1.12-INT-002.
- **RISK-004 – Auto-renew worker fails silently:** Mitigated by 1.12-INT-003, 1.12-INT-004, 1.12-INT-005, 1.12-E2E-001.
- **RISK-005 – Disabled channels get re-subscribed or never unsubscribed:** Mitigated by 1.12-UNIT-004, 1.12-INT-003, 1.12-INT-006, 1.12-E2E-002.
- **RISK-006 – Misconfiguration hides failures or disables renewals:** Mitigated by 1.12-UNIT-002, 1.12-INT-005, 1.12-UNIT-005.

## Recommended Execution Order

1. Run all P0 unit tests (1.12-UNIT-001, 1.12-UNIT-003) to fail fast on logic regressions.
2. Execute P0 integration tests (1.12-INT-001, 1.12-INT-002, 1.12-INT-004) before deploying migrations or workers.
3. Run the remaining integration test set (1.12-INT-003, 1.12-INT-005, 1.12-INT-006) to validate query and guardrail behaviors.
4. Execute E2E journeys (1.12-E2E-001, 1.12-E2E-002) on staging.
5. Close with supporting P1/P2 unit tests (1.12-UNIT-002, 1.12-UNIT-004, 1.12-UNIT-005) to verify observability and configuration defaults.
