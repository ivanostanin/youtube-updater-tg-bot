# Test Design: Story 1.2

Date: 2025-11-20  
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 12
- Unit tests: 6 (50%)
- Integration tests: 5 (42%)
- E2E tests: 1 (8%)
- Priority distribution: P0: 6, P1: 6, P2: 0, P3: 0

## Test Scenarios by Acceptance Criteria

### AC1 – Backup script uploads to OCI-compatible bucket while preserving AWS defaults

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-UNIT-001    | Unit  | P0       | `perform_backup` writes namespace-prefixed bucket paths and checksum metadata     | Pure logic best covered with deterministic unit test to protect data-integrity-critical behaviour |
| 1.2-UNIT-002    | Unit  | P1       | `perform_backup` raises `FileNotFoundError` when database missing                 | Ensures graceful failure path without object storage calls                                        |

### AC2 – Restore script fetches most recent backup and validates checksum

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-UNIT-003    | Unit  | P0       | `restore_latest_backup` selects latest object and restores payload                | Pure data selection + checksum logic; failure would lose newest data                              |
| 1.2-UNIT-004    | Unit  | P0       | `restore_latest_backup` surfaces checksum mismatch errors                         | Guards against silent data corruption                                                             |
| 1.2-INT-001     | Integration | P0 | `scripts/restore-db.py` CLI skips gracefully when bucket configuration missing    | Validates CLI behaviour in real startup path; prevents pod crash (ties to REL-001 risk)          |

### AC3 – Startup auto-restore recovers database when missing

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-UNIT-005    | Unit  | P1       | `ensure_database_backup` no-ops if database already exists                        | Pure control flow; ensures idempotent behaviour                                                   |
| 1.2-INT-002     | Integration | P0 | `ensure_database_backup` restores from latest backup when DB absent (log + file) | Validates interaction between config builder and restore helper                                   |

### AC4 – CronJob executes backup daily with injected configuration

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-INT-003     | Integration | P1 | Render CronJob chart to verify schedule, PVC mount, and storage env vars          | Template-level regression ensures K8s job matches requirements                                    |

### AC5 – Helm values expose OCI object storage configuration

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-INT-004     | Integration | P1 | Helm configmap/secret render exposes object storage keys and secrets              | Validates configuration wiring across templates                                                   |

### AC6 – Unit tests cover backup/restore/startup helpers

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-UNIT-006    | Unit  | P1       | `build_storage_config` respects CLI overrides vs environment defaults             | Logic-only validation; prevents configuration regression                                          |

### AC7 – Manual validation against OCI-compatible endpoint

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-E2E-001     | E2E   | P0       | Drill: run backup + restore using MinIO/OCI endpoint, then start bot with empty DB | Critical recovery flow spanning scripts + application; only possible with environment in loop     |

### AC8 – 30-day retention policy documented and actionable

| ID              | Level | Priority | Test                                                                              | Justification                                                                                     |
| --------------- | ----- | -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1.2-INT-005     | Integration | P1 | Validate lifecycle policy snippet applies to bucket (dry-run or unit CLI wrapper) | Ensures documented command enforces retention before production                                   |

## Risk Coverage

- **REL-001** (startup crash when storage config absent) mitigated by scenarios 1.2-INT-001 and 1.2-INT-002.
- **TEST-001** (CLI lacks regression coverage) mitigated by scenarios 1.2-INT-001 and 1.2-UNIT-006.

## Recommended Execution Order

1. P0 unit tests (1.2-UNIT-001, 1.2-UNIT-003, 1.2-UNIT-004)
2. P0 integration tests (1.2-INT-001, 1.2-INT-002)
3. P0 E2E drill (1.2-E2E-001)
4. Remaining P1 unit/integration tests (1.2-UNIT-002, 1.2-UNIT-005, 1.2-UNIT-006, 1.2-INT-003, 1.2-INT-004, 1.2-INT-005)

## Coverage Gaps & Notes

- No automated coverage for AC7/AC8; maintain documented manual procedures until integration environment available.
- Consider Helm chart unit tests or policy-as-code checks to automate lifecycle policy verification.
